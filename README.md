<summary><b>📝 Etapa 1: Benchmarking de perfis (reflexão)</b></summary>

Ao analisar os 10 perfis, percebi que os mais fortes não são os que têm mais elementos, e sim os que comunicam rápido quem a pessoa é. Diego Fernandes e Mayk Brito se apresentam em poucas linhas, com badges de contato em uma única cor, enquanto Sarah Drasner e Felipe Fialho contam a própria trajetória em um texto curto. Outro padrão foi mostrar a stack com ícones em vez de listas de texto, como fazem Rafaella Ballerini e Jakeliny Gracielly, sem passar de uma dúzia de tecnologias. Nos repositórios em destaque, os nomes são descritivos e em kebab-case, e o README explica o problema resolvido, mostra uma imagem e ensina a rodar o projeto. Também notei que todos os projetos que verifiquei têm licença, quase sempre MIT, e que o .gitignore está presente sempre que há dependências. Por outro lado, vi que estatísticas automáticas podem sair do ar e poluir o perfil, então usei com moderação. Com base nisso, reescrevi meu README em formato de apresentação curta, troquei a lista de tecnologias por badges, adicionei LinkedIn e e-mail e fixei meu projeto deste semestre no topo. Também padronizei o README desse projeto com visão geral, tecnologias, passo a passo de execução, prints e licença MIT. A maior lição foi que o GitHub precisa ser entendido em poucos segundos por quem não me conhece.
